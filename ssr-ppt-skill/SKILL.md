# SSR-PPT-SKILL

把目标、证据、叙事和视觉制作连接起来，交付重点清楚、让人记住、用户能继续修改的演示。

- **门槛（必须达到）**：事实与关键条件准确，文字可读，对象符合编辑要求，遵守模板与交付范围。
- **目标（在设计自由允许的范围内尽量达到）**：有清楚的视觉概念，关键页值得单独截图分享。公司模板任务的目标是在模板之内做到精致。达不到时说明差距，但不为效果牺牲门槛。

本文路径相对于本 Skill 目录。五阶段是一条流程，参考文件在需要时读取，不逐个运行多套清单。

## 共同约定

- 优先使用用户已有材料、品牌、模板与明确要求。未指定格式时交付 HTML＋PPTX 和 `planning.md`；只指定一种就只做一种。精确 N 页包含封面与结束页；只要大纲或样稿时止于约定阶段，局部修改不自动重做整套。
- 事实、单位、时点、状态和改变结论的条件必须保留。关键事实缺失可交付标明缺口的阶段稿，不能虚构或删掉缺口后称完整成品。
- 配方、版式原型、字号比例、颜色面积与数量建议都是推荐起点：合适就用，不合适就改或自定，不为凑模板删除信息。门槛、交付要求和模板约束不能替换。
- 保存一份能指导制作的逐页策划；实际预览最终格式。解析成功、对象存在和模型自评分均不等于验收通过。
- 默认由当前智能体完成，不强制其他模型或子智能体。Web Brain / Inner Web Brain 仅在用户为当前任务明确要求时使用。
- 保留用户原件。制作授权不自动包含安装、部署、提交或发布；已明确授权的操作按其范围执行。

## 沟通模式

先继承用户已表达的偏好，例如“需求明确时连续完成”“遇到问题可以问我”。偏好尚未明确时，先只问一次：“遇到关键缺口，允许我逐个询问，还是由我自行判断并连续完成？”得到答复后再按所选模式进行；不将沉默视为选定模式，等待时可以先读材料、做不依赖答案的准备。

- **允许询问**：先读材料，再一次问一个会实质影响结果的必要问题，收到回答后决定下一问；同时继续不依赖答案的工作。需求充分后直接制作，中途遇到必要问题仍可问。
- **自主执行**：按用户要求 → 材料／品牌／模板 → 目标与使用场景 → 可调整的设计假设决策，过程不追问。事实不足明确标记或降低结论强度；权限不足时完成独立可做部分并说明阻碍。
- “这个你决定”通常只授权当前问题，“后面都不要问”才改变后续模式。用户主动补充时随时吸收。
- 大纲、策划、方向比较和内部验收不自动成为审批关卡；常规字体、布局与配色自行判断。

## 1. 明确任务

在策划稿开头简记目标、受众、现场讲述／独立阅读、材料、页数、格式、模板和重要限制。优先整理用户资料，只有需要外部事实、时效信息或用户要求检索时研究。来源与素材记录按 [planning.md](references/planning.md) 保存。

## 2. 形成策划

按内容表达方法归组事实，确定叙事与逐页信息，再决定图片、图解、图表、矩阵或文字。汇报可结论先行，教学与故事按理解顺序组织。每页用短句记录主信息、依据与关键条件、表达方式、阅读顺序、素材和编辑要求。共同规则写在全稿层；局部修改只更新受影响部分。

内容与视觉选择相互校准。配方和原型有合适的就改编，没有就自定；不能把整份报告直接缩小贴到页面上。真实证据使用真实素材，概念氛围可搜索或用专用生图工具，关系信息考虑 SVG／原生图形。

## 3. 设计与适配

方向已明确时，直接做最能暴露风险的代表页，例如最长的标题、最复杂的关系图、最密的数据页。方向不明确且有设计自由时，先为封面或关键页做 2–3 个明显不同的方向（构图或尺度策略不同，不只是换色），并排看过后自行选定。页数多不等于要多做样稿。

- **新建双格式**：HTML／SVG 代表页 → 原生 PPTX 代表页，验证文字、关系、数据与编辑操作后推广；共用内容、数据、素材和关键几何关系。参见 [双格式样例](examples/dual-format/README.md)。
- **模板／局部修改**：先保留母版、版式、占位符、主题与共享样式，直接处理原生 PPTX；所需 HTML 在模板约束内适配。
- **仅 HTML／仅 PPTX**：只制作约定成品；仅 PPTX 可按实际收益借助 HTML 草稿。
- 实现失败时区分内容、布局、对象实现和环境，保留信息及编辑要求，调整非核心效果或改为原生优先。不能用整页截图代替可编辑交付。

HTML 内联 `assets/player.css` 与 `player.js`，按许可嵌入所需字体和媒体。PPTX 按 [对象合同](references/pptx.md#对象合同) 制作；自绘矩阵不强制原生表格，统计图表默认保留底层数据编辑。公司模板默认不运行全局主题字体覆盖。

## 4. 实际预览验收

按 [visual-review.md](references/visual-review.md) 对照策划，检查信息保真、图形语义、阅读层级、视觉表现与使用场景。

1. 实际打开最终 HTML，先处理 `preview.py html` 版面检查的错误，再逐页查看完全揭示状态，检查离线、字体图片、交互、窄视口及打印；必要时查看播放过程。当前模型不能看图时，按 visual-review 的“不能看图时”处理，并如实写明。
2. 重新读取、渲染最终 PPTX 并逐页看图。按编辑要求在副本中修改指定对象、保存、重开，核对同一目标的预期变化；分组、图表和矩阵分别覆盖。最终成品不含测试改动。
3. 记录“通过、失败、未执行、工具不支持、不适用”及任务是否要求该项。脚本的严格模式只汇总其覆盖的自动检查，仍需实际看图；必需能力未执行或不支持不能算完成。
4. 门槛通过后，有设计自由时按 visual-review 的“出彩检查”自查高冲击页和整套辨识度，有具体可改之处就改；公司模板任务检查模板内的精致度。这是目标，不是门槛。
5. 修复后复查受影响页面；共享数据、主题或字体改变时检查全部受影响范围。双格式分别验收，核对重要内容、条件和关系。
6. 只报告实际使用的工具与范围：库层重开、LibreOffice 渲染、WPS 或 PowerPoint 实机操作分别说明。缺项时交付阶段稿或说明限制。

## 5. 完成交付

交付约定的成品与 `planning.md`，按需附来源和经许可可分发的字体或安装说明。策划中简述实际验收范围与未完成项；源码、截图和测试副本保留在私有构建目录，用户需要时提供。给出真实文件路径；agent 自带的预览面板（如 Codex 的 `open_in_codex`）可以展示成品，但不能替代预览验收。

达到要求后停止。好设计不止一种，视觉表现按目标和受众判断，不规定 SVG、卡片、字数或高潮页的数量。

## 环境与工具

动手前先运行 `python scripts/doctor.py`（只用 Python 标准库）。它报告当前环境有哪些能力，并给出建议的制作与验收路线。按能力选路线，不按 agent 品牌选：

| 能力 | 具备时 | 不具备时 |
|---|---|---|
| 查看图片：多模态模型，或 agent 的读图工具、视觉插件 | 打开 `preview.py` 生成的 PNG 逐页看图 | 以 `preview.py` 的自动版面检查为主，并在报告中写明“未看图，仅自动检查”；有条件时请用户看图 |
| 浏览器：Playwright＋Chrome／Edge／Chromium，或 agent 自带的浏览器工具 | `preview.py html` 截图、交互、打印与版面检查 | 只能做 HTML 结构检查，截图、交互和版面检查标为未执行 |
| LibreOffice＋PyMuPDF | `preview.py pptx` 渲染 PPTX 并做版面检查 | `preview.py pptx --edit-test` 仍会做对象清点、字体与编辑测试；渲染和版面检查标为未执行 |
| python-pptx | 新建 PPTX（默认路线，借助 `scripts/pptx_kit.py` 的基础操作）、模板修改、编辑测试 | 用已安装的其他原生库，例如 PptxGenJS |
| Node.js＋PptxGenJS | 新建 PPTX 的另一选择 | 不必安装 |

agent 特有的能力可以直接复用，例如 Codex 桌面的官方 presentations 环境（见 [pptx.md](references/pptx.md)），或 agent 自带的浏览器与文件预览面板。预览面板只用于展示，不能替代上面的检查。

先检查依赖，按现有授权安装到隔离的构建环境，不更改无关项目的依赖。工具缺失时说明受影响的范围；生成库能打开模板不证明全部对象保真。用户用 WPS 或 PowerPoint 观看时，LibreOffice 渲染只是近似，已知差异见 [pptx.md](references/pptx.md)。
