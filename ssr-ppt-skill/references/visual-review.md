# 方向探索、代表页校准与审美验收

新建或美化演示时使用，与内容、交互及原生可编辑性检查一起执行。审阅对象是实际渲染后的页面图像；代码、对象清单和评分只提供辅助信息。截图、总览图和测试图可用本 Skill 的 `scripts/preview.py` 生成（见文末）。

## 先发散：比较两到三个方向

大约 6 页以上的新建或整体美化任务，在批量制作前先做方向比较：

1. 取封面和一个最能代表全套的关键页（通常是核心结论页或主要数据页）。
2. 为它们做 2–3 个**明显不同**的方向：不同配方，或同一配方下不同的构图与尺度策略。只换配色不算不同方向。
3. 用真实内容在 HTML 中快速制作并渲染，把同一页的各个方向并排放在一张对比图中查看。
4. 按下文的“出彩检查”和受众场景评判，选定一个方向或融合，把取舍理由写进策划稿。

5 页以内的短演示可以只比较两个封面方向。用户明确要求先看样稿时，把这些方向交给用户选择并止于此；否则自主选定后继续，不增加确认关卡。用户指定了模板或明确风格时跳过这一步。

## 再收敛：代表页校准

选定方向后，完成少量能暴露设计问题的代表页：封面、典型内容页、数据或复杂信息页，按实际包含的页型选择。代表页使用真实内容和接近最终长度的文字，不能用短占位词或空白图框掩盖拥挤。检查最长标题、中文断行、素材裁剪和密集信息是否都适合选定方向。双格式任务要渲染两种格式的关键代表页，不能只看 HTML 就假定 PPTX 相同。

发现问题就修改构图或视觉规则，回写策划稿，再推广到全套。已有演示局部修改时，选受影响的页面校准。

## 看整套

把全部最终页面排成缩略总览：

- **缩略图测试**：每页缩到约 240px 宽时，焦点仍能一眼分辨。分辨不出就说明主次不够。
- **节奏**：能量起伏与策划一致；高潮页确实最突出；没有三页以上无理由的同构图同密度。
- **一致性**：字体、色彩角色、对齐位置与形状语言全套统一；母题出现在计划的位置。

总览只用来看节奏和一致性，不能用来判断小字是否可读。

## 逐页审阅

逐张查看完整尺寸的页面，并在实际演示尺寸下检查阅读效果：

| 检查项 | 观察依据 | 常见修正 |
|---|---|---|
| 焦点 | 第一眼能找到主题或主要证据，重要性与视觉面积相符 | 重排主次、缩短标题、放大关键图形、弱化竞争元素 |
| 层级与阅读顺序 | 标题、证据、解释和口径容易区分，视线不用来回跳 | 拉开字号与字重，调整分组和标注位置 |
| 构图与留白 | 挂在网格上，主体比例合适，留白有方向，没有意外空洞 | 改变元素面积和位置，统一边距，调整文本框内边距 |
| 素材与主题 | 图片主体清楚、裁剪自然、调色统一，能说明与内容的关系 | 更换或重新裁剪素材，必要时改用排版表达 |
| 中文与数据 | 断行自然，正文与标注可读，数字单位完整，图表比例准确 | 重排文字，调整图表与直接标注，核对实际字体 |
| 反模式 | 对照 [anti-patterns.md](anti-patterns.md) 没有无理由的命中 | 按清单中的“改为”修改 |
| 版式适配 | 版式服务于内容：没有为套用配方或原型而凑内容、删内容或扭曲内容 | 修改原型或改为自定构图 |
| 使用场景 | 现场讲述能扫读，独立阅读能理解，模板要求得到保留 | 调整密度与解释位置，不擅自删除必需信息 |

## 出彩检查

“没有重叠”“看起来整齐”只说明没有错误。以下检查判断是否足够好：

- **去品牌测试**：遮掉 logo、公司名和标题文字，这套页面能否和通用模板或常见的 AI 生成演示区分开？不能就回到视觉定调，加强母题、尺度和素材。
- **截图测试**：是否至少有 1–3 页值得单独截图分享？高潮页做不到时，优先投入这些页面。
- **模糊测试**：把页面模糊到看不清字，剩下的最显眼的形状是否正是策划的焦点？
- **灰度测试**：去色后层级是否仍然成立，强调是否仍能分辨？做不到就说明过度依赖颜色。
- **精修**：
  - 边距与对齐用像素核对；大字和引号按视觉边缘做光学对齐。
  - 没有孤字和行首标点；数字与单位不断开。
  - 全套标题位置一致；页码、来源等小字的位置与样式统一。

改进优先改尺度、构图、素材和文字质量，而不是加阴影、渐变和装饰。

## 修复与停止

在私有构建目录简短记录页码、观察到的问题、调整和复查结果。优先处理影响理解、阅读、事实或编辑的问题，再处理不够出彩的问题。

修复后重新导出并查看受影响页；全局字体、配色或间距规则改变时检查全套。HTML 和最终 PPTX 分别渲染验收。两者有视觉差异可以接受，但重要内容、焦点和编辑要求不能丢失；PPTX 以重新读取最终导出文件后的图像为准。

同时满足以下条件时完成：

1. 内容与事实正确，实际渲染可读，没有尚未解决的具体缺陷。
2. 没有无理由的反模式命中。
3. 高潮页达到策划的冲击力，并通过去品牌测试。
4. 节奏与一致性符合策划。

确实受能力、素材或时间限制而达不到出彩标准时，说明具体差距和原因，不用模型评分掩盖。审美记录留在构建目录，不额外打包成用户未要求的报告。

## 预览工具

`scripts/preview.py` 依赖 Python 的 Playwright（使用已安装的 Chrome / Edge 或 Playwright 自带的 Chromium）、Pillow，处理 PPTX 时还需要 LibreOffice 与 PyMuPDF：

```bash
# HTML：逐页截图（完全揭示状态）、记录控制台与外部请求、小视口截图、打印 PDF 页数，并生成总览
python scripts/preview.py html build/index.html --out build/review/html

# PPTX：经 LibreOffice 转 PDF 后逐页渲染，统计每页原生对象，可选做编辑测试
python scripts/preview.py pptx build/deck.pptx --out build/review/pptx --edit-test

# 任意图片：生成总览、灰度版与模糊版
python scripts/preview.py sheet build/review/html/slides --out build/review/html/sheet.png

# 方向比较：把多张图片并排放在一张对比图中
python scripts/preview.py compare a/01.png b/01.png c/01.png --out build/review/cover-compare.png
```

生成的 PNG 要实际打开查看：Claude Code 用 Read 读取图片，Codex 用其图像查看能力。LibreOffice 的渲染结果与 PowerPoint 存在差异（字体度量、图表样式），只能视为近似；报告时说明使用了哪个渲染器。
