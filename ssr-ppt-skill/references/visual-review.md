# 预览、编辑与视觉验收

三种手段各管一件事，缺一不可：
- 自动检测找结构与运行问题；
- 实际看图判断信息与视觉；
- 在目标应用里操作，验证用户需要的编辑行为。

看图指主模型直接查看最终渲染页面。生成了截图、写了“已查看”、OCR 或自动检查通过，都不算看过图。本技能只供能看图的模型使用，见 [SKILL.md](../SKILL.md) 的“使用前提”。

## 制作前和代表页

先继承沟通模式。方向明确、模板固定或局部修改时直接处理；方向不明确且有设计自由时，比较少量结构不同的方向，不只换色。内部探索无需自动成为用户审批。

挑能暴露风险的内容：长中文、复杂关系、密集数据、特殊字体、图片焦点、模板占位符或目标应用兼容性。新建双格式核对 HTML／SVG 与原生 PPTX 代表页；简单短稿可把完整初稿作为验证对象。不按页数机械增加样稿。

## 四层规则

- **底线**（必须通过）：
  - 事实和口径准确，关键条件可见；
  - 版面完成：主次清楚，没有意外的遮挡、挤压或线条穿字，位置和间距的组织一致、讲得通，图形不错误表达关系或数值，最终文件的实际字号在使用场景下可读；
  - 修复意外孤字、违反中文排版禁则的标点断行，以及妨碍理解的数字与单位分离；有意且清楚的视觉分组不算缺陷；
  - 对象符合编辑合同，约定格式正常使用。
- **默认方法**：结论式标题、网格、少量强调色、直接标注、留白等，按场景调整。
- **设计自由**：构图、方向、字体、密度、用图与节奏可以不同，不必向配方看齐。
- **目标**：底线之上追求记忆点，见下文的“出彩检查”。达不到时说明差距，不算失败，也不为它牺牲底线。

诊断线索见 [anti-patterns.md](anti-patterns.md)。好设计不止一种，不用唯一风格或模型自评分代替看图判断。

## 实际检查顺序

1. 信息：对照策划与来源，检查证据、状态、数字、分母和例外。对承载业务含义的箭头、连线、分组、回路和标签，核对其主体、方向与含义是否有材料依据；装饰线和分隔线不作业务关系核对。
   图示优先时逐页再问三点：哪些重要信息已由图直接表达？哪些段落适合转图，却只是装进了卡片？图示后关键条件是否保留、重复说明是否减少？看的是关系是否更易懂、信息能否还原，不用图形数量、字数下降或自动检查通过代替判断；更多更复杂的图也可能更难懂。
2. 全套总览：看节奏、主次、一致性和适当变化，例如是否连续重复同一种卡片结构、各页重点是否都用同一种力度。跨页引用的数量、名称和页码一致。高冲击页按传播需要使用，不凑数量；固定公司模板也能通过。
3. 每页完整尺寸：实际查看这页最终渲染图。第一眼最突出的是什么？它是不是本页主信息？接下来看哪里，顺序清楚吗？有没有主内容过小、文字过密而空间闲置，或所有元素一样抢眼？再检查标题断行、线条穿字、遮挡、图例与标签、单位、标点、实际字号、数据尺度、图像、边缘和投影可读性。指出具体位置、影响和最值得做的修改；没发现问题就写核对了什么，不为记录编造问题。
   - 留白不设面积上限，按它是否帮助聚焦、建立层级和组织阅读判断。主内容过小或拥挤、同时有可利用的闲置空间，或空带割裂了阅读顺序，就调整布局；模板中有明确作用的大块留白可以保留。
   - 对齐要求一致、讲得通的组织关系，允许有意错位。第一眼落点和策划不一致时，可以改页面，也可以按更好的表达更新策划。
   - 灰度／模糊图只是辅助诊断。
4. 实际使用：HTML 离线、翻页、揭示、窄视口、打印；PPTX 重开、渲染与编辑；同时核对备注和必要链接。
5. 双格式：信息、条件、数据、关系与重点一致，无需像素完全一致；说明有意义的差异。
6. 修复：内容问题回策划，排版／实现问题回制作。复查受影响页面；共用数据、主题、字体变化覆盖全部受影响范围。

看图记录与任务规模相称：写发现的问题、所做修改、受影响页面和复查结果；没问题的页简记看了什么，不能只写“通过”。这是内部验收，不增加审批。

## 出彩检查（目标，不是门槛）

“没有重叠”“看起来整齐”只说明没有错误。底线通过后，有设计自由时用以下问题自查：

- **去品牌测试**：遮掉 logo、公司名和标题文字，这套页面能否和通用模板或常见的批量生成演示区分开？不能就回到视觉定调，加强母题、尺度与素材。
- **截图测试**：有没有 1–3 页值得单独截图分享？没有时，优先投入封面、核心结论或最强证据页。
- **模糊测试**：模糊到看不清字时，最显眼的形状是否正是策划的焦点？
- **灰度测试**：去色后层级是否仍然成立？做不到就说明过度依赖颜色。
- **精修**：边距与对齐按像素核对，大字和引号做光学对齐；全套标题位置、页码和来源小字的样式统一。

改进优先从尺度、构图、素材和文字质量入手，而不是加阴影、渐变和装饰。

公司模板任务不做去品牌测试，改为检查模板之内的精致度：是否完全对齐模板网格，层级是否比原稿清楚，图表与表格是否去掉了默认样式。

## 编辑验证

按 [pptx.md](pptx.md) 定位具体页和对象。普通文字、自绘矩阵数字、组内说明、统计图和图片分别选实际目标，不用一个成功文本框代表全套可编辑。

副本修改 → 保存 → 重开 → 核对同一目标的预期值 → 渲染查看。图表同时验证缓存与内嵌工作表；连线、联动标签测试所需行为。测试标记不进入交付文件。

## 脚本与证据

```bash
python scripts/preview.py html build/index.html --out build/review/html --strict
python scripts/preview.py pptx build/deck.pptx --out build/review/pptx --edit-test --edit-targets build/edit-targets.json --strict
```

没有 LibreOffice 时，PPTX 命令加 `--pdf <由最终 PPTX 导出的 PDF>`，见 [pptx.md](pptx.md)。

脚本生成逐页 PNG、总览、灰度／模糊图、版面检查标注图、报告和独立测试副本。打开看过才算视觉检查。版面检查的错误必须处理；警告（包括线条穿过文字）逐条看图判断，确认无误的写明理由。

两个命令都会列出每页正文字数（不含标题、表格和页脚区）。图示优先时加 `--visual-first`，脚本会指出超过约 60 字的单段文字，以及总字数超过约 60 字的文字卡片或列表（西文一个词按 2 字计）。这只是复查线索，不算通过或失败：能转图的转图；确需保留的写明是哪部分、为什么；不要靠删条件降字数。

## 检查状态

| 状态 | 意义 |
|---|---|
| passed／通过 | 执行并取得证据，只在报告覆盖范围内成立 |
| failed／失败 | 与要求不符，修复后重测 |
| not_run／未执行 | 尚未做或被跳过 |
| unsupported／工具不支持 | 当前方法不能覆盖，需换方法或说明限制 |
| not_applicable／不适用 | 本任务没有此要求，记录原因 |

同时标注是否必需。必需项未执行或不支持，不算完成；可交付阶段稿但明确缺项。严格模式只汇总覆盖的自动检查，人工检查保持未执行，由 Agent 在策划或验收记录中补实际看图与操作证据，不篡改自动结果。对象或字体存在不能单独证明行为和视觉正确。
