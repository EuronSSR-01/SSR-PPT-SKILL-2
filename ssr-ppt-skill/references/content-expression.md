# 内容组织与信息表达

用于新建内容、实质改写及流程机制。方法可替换，事实保真不可省略。数据操作的完整检查见 [charts.md](charts.md)，编辑要求见 [pptx.md](pptx.md)。

## 最短判断路径

1. **主信息与依据**：精读材料，区分事实、计算、解释、假设和建议。标出单位、时点、实际／申请／预计状态，以及改变结论的关键条件。
2. **观众任务**：查精确值、比较差异、理解过程或机制、识别场景，还是阅读解释？已有合适形式直接采用，不遍历所有图型。
3. **提炼并安排去处**：删冗词、归组、分段和拆句；当前页、后续页、备注、附录各承接适合的信息。关键条件在页面可见，不通过省略制造好看的错误结论。
4. **关系／计算成立后再增强表达**：连线含义和派生指标有依据，再写更有力的标题与视觉。
5. **还原检查**：观众能否从成品正确复述主要事实、关系及限制？图示优先时，适合转图的信息不停留在段落和要点里；图文均可时，图解未更清楚就保留组织良好的文字。

## 八项方法

| 方法 | 适用与动作 | 可观察产物 |
|---|---|---|
| 观点与证据 | 决策／说服任务将事实归组，写证据支持的结论；教学和故事按理解顺序展开 | 连读标题能理解叙事，标题不超出证据 |
| 文字提炼 | 按主题与功能分段，精简重复，再分配主页面、后续、备注和附录 | 主页面可扫读，关键条件有去处；独立阅读能自足 |
| 阅读顺序 | 定第一眼、证据和解释，再分面积、字重、位置与留白 | 不需来回寻找标签、主体或来源 |
| 对象与关系 | 提取参与者、动作、类型、方向和条件，再画流程、架构或机制 | 节点与连线可由材料逐项解释 |
| 数据提炼 | 先核口径、包含关系、时间基准、去重与加权，再算比例／差额 | 原值、公式、精度和派生结论可复核 |
| 表格重表达 | 先判断查数、比较、趋势、构成或异常，再选择精简、聚合、矩阵或图表 | 对应清楚，关键异常、数值和限制不消失 |
| 全套节奏与收尾 | 按难度与重要性分配篇幅，连读标题；决策汇报明确希望得到的回应 | 重点得到足够解释，结尾与目的相符 |
| 代表页校准 | 用真实长度及复杂度验证最长标题、密集内容和关键图解 | 所需格式均成立，结果回写策划 |

金字塔结构适合先判断后论据的沟通，不要求每个故事、课程或单页都套同一提纲。并列分组尽量互不重叠，声称完整时检查是否遗漏；分类不完整就说明范围。

## 表达方式

开场由用户选择，规则见 [SKILL.md](../SKILL.md) 的“开场两问”和“表达方式”。未选择时按图示优先。

- **图示优先**：主动找出能转成图的信息，让图形承担过程、关系、构成、比较和变化；页面文字留给标题、标签、关键数字、条件和必要解释。
- **图文均可**：按观众任务和现场讲述／独立阅读选择图、表或文字，允许说明较充分的文字页。

### 图示优先怎么做

先提取、再选图、最后补字：对象、关系、数据和条件 → 主图 → 标签与必要文字 → 对照原文。每页先问观众要理解什么，哪些信息能被位置、分组、连线、尺度直接表达；不遍历所有图型，也不给每页做多个备选。

下表是选择起点，不是封闭清单，可以自创表达：

| 文字里的信号 | 可选的图 | 先核对 |
|---|---|---|
| 谁对谁做什么、先后、交接 | 流程、泳道、关系图，条件写在箭头旁 | 方向和条件有材料依据 |
| 现状与建议、调整前后 | 现状／建议对照图 | 两种状态分开标注，不把建议画成已执行 |
| 总量与组成、占用与剩余 | 堆叠条、比例条、构成图、进度 | 包含关系、口径与时点一致 |
| 数量比较、排名、差距 | 条形图、点图 | 口径可比；不可比时分开呈现或保留文字 |
| 随时间变化 | 折线、柱形、时间线 | 期间与时间基准 |
| 多个对象在相同维度上比较 | 比较矩阵、点阵 | 每格都有依据，缺项写“材料未述” |
| 地区分布 | 地图高亮、分组条形 | 地区归属与计数口径 |
| 计划、步骤、里程碑 | 时间线、阶段图 | 已完成／计划／预计状态 |
| 比例、分成、目标值 | 比例条、关键数字 | 分母与各部分的主体 |
| 定义、承诺范围、例外条件 | 精简文字，就近对应相关图形 | 含义准确；同页其他关系仍照常图示 |

以下做法能改善外观，但不能据此声称已经图示化：

- 长段落外面套一个框，或把要点平均分进几张卡片；
- 每段配一个装饰图标或编号；
- 把原文原样做进 SVG 或图片；
- 加照片或背景图，解释机制和差异仍全靠正文；
- 每页顶部一排数字卡片，下面仍是要点。数字卡片可以用，但不替代主图。

反过来，短标签节点、矩阵和分组卡片可以是有效图示，前提是布局确实表达了关系。

### 边界

- **不补造**：箭头方向、因果、上下级、包含、比例、可比性和责任都要有材料依据。例如同行数字口径不明时，不与本方数据画成并排柱形；材料只写了一个方案的优点，不能给其他方案打叉。不能为了让流程看起来完整而补画材料没有支持的循环或返回关系，箭头、回路和标签不能补出责任或因果；材料已经支持的循环关系，可以用闭环表达。
- **不丢**：单位、期间、实际／申请／预计状态、前提、适用对象和例外。少字来自图形承担了关系，不靠删条件。
- **不混**：主体、关系方向和状态与数字一样要准确；现状、条件、目标与建议分开标明。例如现行规则里的门槛值不写成建议，提出的目标不画成已达成。
- **自足**：独立阅读稿不能把理解结论必需的信息全放进备注；附录和拆页服从约定页数与交付范围，不为图示增页。
- **明细**：需要逐项核对时保留明细表，可聚合重复、突出关键列，或在页数允许时改为概览页加附录。

## 文字转图解

提取一份小型关系清单即可，无需另建框架：

- 对象：谁或什么？动作：谁对谁做什么？
- 类型：先后、包含、依赖、信息、资金、责任或其他明确关系。
- 方向与条件：是否双向、是否有分支、哪些前提成立时才发生。

顺序用流程／时间线，层级用架构，责任交接用泳道，反馈用回路，比较用共同维度矩阵。无依据的上下层级、因果和确定箭头不补画；名词放进盒子并不等于讲清机制。复杂关系可拆分视图，颜色、线型、分组与标签共同表达，不让所有关系挤在同一个箭头上。

HTML 可用语义清楚的 SVG；PPTX 对应有意义的文字、形状、连接和分组。对象不要拆成难以选择的无意义碎片。关系正确后再精修对齐、路径、线宽与标注。

## 什么时候保留文字

定义、限制、承诺范围、例外条件或短引言，若画图只是把每句话套进框里，保留分层文字更清楚；数值密集且需查精确值时保留表格或附录。

- **图示优先**：按信息单元判断，不整页豁免。一页含有必须准确保留的条件，不等于整页都不用画；策划里写了理由，也不等于理由成立。逐段问：
  - 哪句必须用文字准确表达？
  - 这段里哪些关系可以交给位置、连线、分组或尺度？
  - 转换后主体、方向、口径、状态、前提和例外还在吗？
  - 不画图，是因为图更难懂、缺少关系依据，还是只是省事？

  保留的文字就近对应相关图形；需要完整措辞的内容，不为凑短句删掉条件。可图示的信息也不必挤进一张复杂大图，可以拆分、分组，配清楚的文字。只写“含关键条件”“需逐字准确”不算理由。
- **图文均可**：文字多先编辑与分配，而非强制图片化。

[worked-examples.md](worked-examples.md) 第 4 例是“保留文字”的案例（同一页里同一天的几个时刻画成短时间轴，不同情形的规则保留文字），第 5 例对照了长段落、仅套框和有效图示。
