# 原生可编辑 PPTX

## 路线与模板保护

- 新建双格式：先做 HTML／SVG 代表页，再用同一份内容、数据和关键几何关系做原生 PPTX 代表页；确认信息、视觉与编辑操作成立后推广。HTML 是设计与预览入口，不是任意网页的自动拆解器。
- 公司模板或已有文稿：先检查主题、母版、版式、占位符、页面尺寸、备注、链接和特殊对象。在副本中直接修改原生 PPTX；仅改约定范围，不重新套配方或无条件覆盖字体。
- 仅 PPTX：直接制作原生文件，按收益选择是否借助 HTML 草稿，不额外交付 HTML。
- 保留原件和基线。生成库能打开文件不证明保存后所有功能保真；检查实际使用的图表、媒体、动画与链接。工具不能保留必需对象时换实现或明确未完成项。

模板先做一个代表页的“打开—修改—保存—重开—渲染”试验。比较未修改页面、母版／版式关系、主题、占位符、备注与链接。字体修复只针对已确认的问题，不默认运行全局覆盖脚本。

## 工具选择

Codex 桌面先用 `mcp__codex_app__load_workspace_dependencies` 找当前 runtime 与库，不硬编码机器路径。官方 presentations 环境可用时读取其当前 implementation／native_evidence／finalization 文档，遵循实际 API。

其他环境复用现有工具：新建可用 PptxGenJS，模板与局部编辑可用 python-pptx／OOXML；本技能的双格式样例用 python-pptx。现有 `pptx` Skill 的技术方法可参考，视觉与范围按本任务约定。

PptxGenJS 的已知要点（4.0.1 实测）：
- 默认 `LAYOUT_16x9` 只有 10×5.625 英寸；要 13⅓×7.5 英寸须设 `pptx.layout = 'LAYOUT_WIDE'`。
- `scripts/preview.py` 的图表自动编辑测试只接受 python-pptx 的内嵌工作表布局，PptxGenJS 生成的图表会如实标为 `unsupported`。图表的数据编辑是必需项时，二选一：用 python-pptx 生成该图表；或在 WPS／PowerPoint 中实际修改数据、保存重开并记录结果。不能把 `unsupported` 当作通过。

渲染可用目标 Office、WPS 或 LibreOffice＋PyMuPDF。字体度量和排版可能不同，报告实际渲染器，不把 LibreOffice 等同于 PowerPoint／WPS 实机验收。LibreOffice 渲染有两个已知差异，看图时不要误判：
- 会自动在汉字与西文、数字之间加间距，叠加手动空格后显得偏宽；PowerPoint 不会这样显示。
- 西文字体本身含汉字时会直接用它显示中文，所以东亚字体缺失的问题在 LibreOffice 中看不出来，要以报告里的字体清单为准。

## 对象合同

合同由内容性质和用户后续操作决定，写在策划中，两种格式共用。

| 内容与操作 | PPTX 形式与检查 |
|---|---|
| 标题、正文、说明、数据标注需改字 | 原生文字，检查目标内容能修改、保存并重开 |
| 需要增删行列、批量粘贴的表格 | 优先原生表格；检查所需单元格及表格操作 |
| 比较矩阵、套餐卡、色块，按格改字和移动 | 可用分组原生形状＋文字；检查格子与移动，不强制原生表格 |
| 条形、折线、占比等统计图表 | 默认原生图表，保留类别、系列、数值、单位和底层数据编辑，检查改值后图形与数据同步 |
| 流程、架构、机制图需逐元素编辑 | 原生形状、文字和连接线；按需检查节点、分组、连接绑定与移动后的关系 |
| 单个大数字、编号、数量型机制示意 | 可用文字／形状；不能把统计图改名为示意图以降低编辑要求 |
| 照片、插画、局部图标、标志 | 独立图片，可移动／裁剪；要求替换则另测替换，不宣称内容逐元素可编辑 |
| 用户要求保留的原图 | 保留并说明编辑范围 |

整页图片或整页 SVG 不满足可编辑文字与图表要求。插入 SVG 不自动成为原生形状、文字或带数据图表。形状图里可改的数字不等于改数据后图形会自动更新；需要联动就实现并验证。

## 单位与排版

约定 HTML 画布宽度 H（px）和 PPTX 宽度 P（英寸）。英寸 = px × P/H；pt = px × P/H × 72；EMU = 英寸 × 914400。只有 96 px 对应 1 英寸时才是 px ÷ 96 和 px × 0.75。样例的 1280×720 对应 13⅓×7.5 英寸，不套到任意模板。

- 新建明确字体、颜色和必要的东亚字体；模板优先继承正确主题／占位符，见 [typography.md](typography.md)。
- 边距、行距与断行服务于阅读层级。溢出先整理内容或调整布局，不用自动缩小掩盖问题。
- 固定元素可用母版／版式，不为少量页面建设复杂体系。
- 图片按焦点等比裁切；图表和矩阵按 [charts.md](charts.md) 美化。
- 讲稿与补充来源可入备注；改变结论的条件、单位与状态在页面上可见。

## 编辑验证与覆盖边界

重新读取最终文件、逐页渲染和实际看图，再在副本中验证编辑。按“页码＋shape_id 路径＋操作”定位同一个对象，记录修改前、预期、实际值；检查重开后的内容和视觉效果。对象数量和已有勾号不能证明修改成功。

```bash
python scripts/preview.py pptx build/deck.pptx --out build/review/pptx --edit-test --edit-targets build/edit-targets.json --strict
```

`edit-targets.json` 为列表，页码从 1 起，路径用原生 shape_id（不是对象下标），分组递归定位。例如：

```json
[
  {"slide": 1, "path": [4], "kind": "text"},
  {"slide": 2, "path": [6, 8], "kind": "text"},
  {"slide": 2, "path": [6], "kind": "move"},
  {"slide": 3, "path": [5], "kind": "chart"},
  {"slide": 4, "path": [7], "kind": "table", "cell": [1, 2]},
  {"slide": 4, "path": [9], "kind": "picture"}
]
```

实际 ID 以文件为准。省略目标时，脚本选择每页／每组首个文字和所有表格、图表、分组、图片，不能替代任务指定的关键数值、说明和矩阵格子。

脚本覆盖：
- 指定文本、表格格子的内容改变及重开；
- 分组位置改变、内部对象 ID 和已有连接端点绑定保留；
- 独立图片裁剪参数改变；
- 单绘图区、单层字符串类别的簇状条形／柱形／普通折线图：修改数值，核对类别、系列、缓存与标准内嵌工作表。其他图型、外部链接、非标准工作表标为 `unsupported`，补专门测试；
- 最终与测试副本渲染、所有主题的字体清单。

脚本不自动验证 Office 拖动节点后连线跟随、图外手写数值联动、图片替换、插行列、动画、字形覆盖或审美质量。所需但未测标 `not_run`，工具做不到标 `unsupported`，不能都记为通过。

`--strict` 要求脚本的必需自动项目全部通过；`manual_review` 仍为未执行，Agent 实际看图并另记证据。未加 `--edit-test` 的严格 PPTX 检查会因编辑测试未执行而非零退出。不能删目标或降级合同来使检查变绿。

需要实机编辑且应用可用时，在目标应用修改、保存、重开；只做库层验证则如实表述。交付原成品，测试标记只在副本。可运行路径见 [双格式样例](../examples/dual-format/README.md)。
